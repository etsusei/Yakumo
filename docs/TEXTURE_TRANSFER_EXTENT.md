# Original resource transfer and texture source extent (ASSET-012)

This is a static audit of the original `NPJB-40001` resource-load transform behind the selected texture source slot. It identifies the operation that changes the destination bytes and the information needed to certify their extent. It does not certify a live load, a successful complete request, or production native dispatch. No game run or original-code oracle execution was performed here.

The supported `profiles/mhp3rd/game/EBOOT.ELF` has SHA-256 `55c0598436c0753b04331f8e95d406f832d9217806e3a896fed0e88b33637d8c`; its relevant file-backed segment maps guest `0x08804000` to file `0x2CB4`. All spans below were hashed directly from that ELF, with exclusive ends and return delay slots where a complete routine is named. The ignored `out/testing/texture-transfer-extent-static.json` records the offsets, hashes, import-report identity, and lookup-table comparison without original bytes.

## Which operation writes decoded bytes

`profiles/mhp3rd/analysis/report_imports.csv` resolves `0x08965928` to `sceKernelDcacheInvalidateRange` and `0x089656A0` to `sceIoRead`. The wrapper at `0x08863608` invalidates the manager's `+0x98C0` staging area for `0x20000` bytes and tailcalls `sceIoRead(fd, manager+0x98C0, descriptor[+8])`. Its return is the I/O import's byte count or error. It is not a decoded length.

Those names identify the original PSP imports, not an observed PSP hardware trace. In the current host, [hle_system.cpp](../profiles/mhp3rd/host/hle/hle_system.cpp) registers `sceKernelDcacheInvalidateRange` as a successful no-op, while [hle_io.cpp](../profiles/mhp3rd/host/hle/hle_io.cpp) copies synchronous file bytes into guest memory and returns their count for `sceIoRead` (or an error for an invalid descriptor). An original-code oracle using explicit import stubs should model the guest-visible memory and return values it needs; its result cannot establish physical PSP cache behavior or timing.

The worker compares that result with `descriptor[+8]` at `0x08865518`; its second read branch at `0x0886595C..0x08865970` makes the same comparison. A different result takes another state path. A matching read still precedes the destination copy and later processing. In the CPU copy branch at `0x08865294..0x088652A8`, `0x088EE470` forwards to the original `0x0880C088` byte copy using `destination = descriptor[+4] + descriptor[+0xC]`, `source = manager+0x98C0`, and `count = descriptor[+8]`. The companion copy at `0x08865350..0x08865368` uses the same pointers and count. The alternate branch at `0x08865268..0x0886527C` writes a literal one through the optional descriptor `+0x14` pointer; this is not a returned byte extent. The surrounding policy, waits, and failure paths are separate completion questions; a successful read alone cannot authorize the selected slot.

The original deobfuscation is `0x088639BC`, reached from the worker's conditional `0x08864BC8` call at `0x08865420`. `0x08864BC8` obtains the same destination and count from the descriptor. When byte `+0x19` is nonzero, it derives a 2 KiB block address from the resource's sector table and chunk offset and calls `0x0886356C` to seed state at `manager+0x2F7DC/+0x2F7E0`. The transform substitutes each destination byte through the 256-byte table at `0x089AF380`, then XORs a key word from `0x08863930`; it modifies the destination in place. The ELF table's SHA-256 is `442d20ebfcc0fbba34b20a28e20fbd72c8a8f330a3342b0122f9e405f4822cc2` and it matches the existing independent `databin.DECODE_TABLE` exactly. This is the size-preserving DATA.BIN deobfuscation described in [DATA_BIN.md](DATA_BIN.md), not a decompressor that reports an expanded size. The worker calls it only when descriptor byte `+0x1B` is nonzero; the other branch leaves the copied bytes verbatim. Enqueue copies manager byte `+0x2F7D4` into `+0x1B`. That per-request branch must be observed rather than assumed for a selected texture request.

For signed positive input length `n`, `0x088639BC` advances its loop by four bytes and therefore reads and writes `4 * ceil(n/4)` destination bytes. A nonpositive `n` produces no transform writes. For positive `n`, the return value is the final key word from `0x08863930`, not a byte count. Thus the meaningful transferred length on a complete, exact-read, size-preserving path is `n` for that fragment, while its memory-write footprint can be up to three bytes larger. The optional SHA-1 update hashes `n`, not the rounded footprint. A slot check must bound both `offset+n` and `offset+4*ceil(n/4)` when the transform runs; a nonaligned final fragment cannot quietly turn neighboring bytes into authorized resource data.

For a sector-table word and chunk offset of zero, `0x0886356C` replaces both zero seed halves with `0x2345` and `0x7F8D`. Each `0x08863930` call advances them as `high = (high * 0x2345) % 0xFFD9` and `low = (low * 0x7F8D) % 0xFFF1`, yielding `(high << 16) | low`. The first three words are `0xAE1DED19`, `0x8CD1EA1D`, and `0x7C542B0D`. For a deterministic synthetic destination initially containing bytes `00 01 02 03`, the independently implemented `databin.decrypt` predicts `D2 7B 98 08`; bytes `00..07` predict `D2 7B 98 08 42 D4 7A 8F`. The second case is also the expected full write footprint of a five-byte original transform call when all eight input bytes are accessible, while only five bytes belong to the logical request. These expectations are pending original-code execution.

`0x088637E0` is a separate SHA-1 path after the destination operation, selected by descriptor byte `+0x1C`. It calls `0x08819E94` to initialize the familiar SHA-1 state, `0x08819AC8` to update, `0x08819C98` to finalize, or `0x0881A0D0` for a one-shot digest depending on the first/last fragment bytes `+0x19/+0x1A`. The input is the destination region and `descriptor[+8]`; digest/state live at manager `+0x2F754/+0x2F768`. These helpers neither copy/deobfuscate the selected source nor return its written extent. The selected enqueue at `0x08863CDC` initializes its `+0x1C` value to zero. When manager `+0x2F7D4` is nonzero, `0x08863EB4..0x08863F0C` conditionally changes it to one; the alternate branch returns to `0x08863D58` and leaves it zero. Thus `+0x1B` can enable deobfuscation while `+0x1C` leaves SHA-1 generation disabled. No probability for that condition is established here.

An original digest comparison exists at `0x08865CD0`, but it belongs to the alternate file-read route. From worker state 1, a halfword at `manager+0x298E8+4*resource_ID` other than `0xFFFF` branches at `0x08865724` to `0x08865858`. That path formats a file under the `ms0:` saved-data directory, opens and seeks it, then reads at `0x0886595C`. An exact read enters `0x08865AEC`; reaching the comparison further requires the `0x088651D0` check at `0x08865B34` to return nonzero, its event wait to finish, and descriptor `+0x1C` and final-fragment `+0x1A` both nonzero. The comparison uses `0x0880BFF4` on manager digest `+0x2F754` and the 20-byte ELF entry at `0x089AF480 + 20*resource_ID`; a mismatch enters the error path. The normal state-8 read at `0x0886550C` instead goes through `0x088659CC`, `0x08865A10`, and `0x088657D8` to retirement, bypassing `0x08865B90` and the comparison even when its digest was generated. Matching a computed digest against the ELF table outside that route does not prove the original worker performed the comparison.

The manager vtable at `0x0896F648` also has `0x08864C54` at `+0x1C`: it seeks, repeats direct `sceIoRead` until the requested count is returned, calls the same seed and in-place transform, and returns that requested count. The selected owner wrapper described in [TEXTURE_SLOT_LIFECYCLE.md](TEXTURE_SLOT_LIFECYCLE.md) submits through manager `+0x30` (`0x08863CDC`), so this direct method is an alternative path, not evidence that the selected asynchronous request completed.

## Small original-code oracle to settle the transform footprint

The manageable leaf is `0x08864BC8` with a constructed manager and 32-byte descriptor, or `0x0886356C` followed by `0x088639BC` to isolate the primitive. Load the supported ELF so the original lookup table is present. Place the manager in mapped RAM with at least `0x2F7E4` accessible; the sector lookup sits at `+0x3A40+4*ID` and the seed state at `+0x2F7DC/+0x2F7E0`. Set descriptor `+2` to a small resource ID, `+4` to a guarded destination, `+8` to the tested count, `+0xC` to an offset, and `+0x19` to 1 for the first fragment. Supply a synthetic sector-table word at the lookup address. The wrapper's `a0/a1` are the manager and descriptor pointers. The primitive's `a0/a1/a2` are manager, destination, and signed count.

Compare original AOT and interpreter RAM, CPU state, return value, and canaries. Generate encoded fixture bytes from a deterministic synthetic plaintext with the existing independent DATA.BIN codec. Test 4, 8, and 12 bytes, a 5-byte call backed by 8 encoded bytes plus an outer canary, zero length, and two adjacent fragments in which only the first sets `+0x19`. The 5-byte case should distinguish five meaningful bytes from eight transformed bytes without an out-of-bounds memory access. Keep the fixture well within the mapped guest range and bound instruction count; large or malformed lengths are unnecessary. The parent gate subsequently executed the real workers for 32-byte synthetic
fragments, a 5-byte rounded-write case, and the complete private entry 01489.
It confirms the five-versus-eight distinction and both copy routes. The proposed
zero-length and multi-fragment leaf cases remain separate future coverage.

To exercise the original digest comparison, a separate bounded worker case must enter the `ms0:` file branch with the lookup halfword other than `0xFFFF`, complete its read and event wait, make `0x088651D0` return nonzero at `0x08865B34`, and set `+0x1C/+0x1A`. For a constructed fixture, `0x088651D0` returns one when byte `+0x2DD` of the object pointed to by global `0x08A38644` is zero. The state-8 DATA.BIN route cannot cover that comparison by toggling flags alone. The expected digest table is fixed in the supported ELF, so a positive comparison also requires a matching source sample; a synthetic transform-only fixture is sufficient for the extent and canary questions but not that success branch.

## Authority needed by production dispatch

For each selected owner generation, observe the queue submission with its distinct request identity, resource ID, destination and planned fragments. Accumulate actual successful destination writes only after each exact-length read, completed copy, and selected transform/verbatim branch. Commit a source extent only after the final fragment has succeeded for that same request and generation, the logical fragments cover one gap-free range, and the write footprints stay inside both the owner's live allocation and the selector-7 `0x5800` slot at `owner+0x27C70..owner+0x2D470`. Carry the measured logical extent into the existing root/child parser and reject a fragment, result, or state transition that leaves the extent unprovable. Invalidate it on cancellation, reset, reload, teardown, or owner-address reuse; queue idle, state 3/4, a cached resource ID, and the requested table length are not completion evidence. Retain original fallback for every rejected or unresolved request. The produced authority must name the exact owner allocation generation, since the pointer alone can be reused.
