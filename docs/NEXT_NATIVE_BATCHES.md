# Next native migration batches

This is the finite execution contract following the module inventory and first user pair. Task status is in [tasks.json](tasks.json). No default-native setting, game-data redistribution or automatic gameplay is authorized by this document.

## Batch A: scale and matrix copy commit their native results

The portable implementations and guest adapters already exist. The first paired session only executed their verify path. A prior historical scale-native route is useful evidence but does not cover the current copy-native path or the new delivery policy.

- **NAT-001 — Offline native execution gate.** Add a declared execution profile that allows exactly scale/copy native and all three other replacements off, while Baseline stays all off and both select all observation probes. Packaging and readiness must stop hardcoding all-verify/old four cases. Add production AOT chained-call checks for the two native overrides. Preserve existing original-code differential coverage and off/fingerprint/fallback checks. The profile must be validated and bound to its catalog/mode declarations; it is not an arbitrary environment override.
- **NAT-002 — Matched local delivery and one fresh case.** Build B0 plus the same current observation revision as candidate, preserve the corrected game font and independent data, use distinct app identities, and pass signed preparation-only readiness. Supply a new versioned village case requiring both scale `0x08878B28` and copy `0x08879D08`. Reuse the already demonstrated short village trigger; do not ask for the former four-case batch again. Keep the older apps and records intact.
- **NAT-003 — User executes the native case.** The user runs both roles from the same registered save/font/configuration, inspects the character, performs the finite walk/camera sequence and closes normally. Target about 5–10 minutes combined, as an estimate. Record outcomes and required native coverage separately.
- **NAT-004 — Analyze and accept or keep disabled.** Require complete compatible records, all checkpoints, normal user marks, clean diagnostics and no in-case configuration change. For each required helper, require certified complete counter windows, Baseline `aot_calls == completed >= minimum`, candidate `native_calls == completed >= minimum`, and zero candidate AOT/verify/fallback calls. Uncertified/incomplete/orphan/mismatched scopes fail the strict pilot gate. Different manual streams still require interpretation; no deterministic replay or speedup is inferred.

A successful native-execution verdict proves the requested replacement actually ran in the tested case. Keep `reference_verification` as `not_covered` when no in-process reference was run; cite the earlier verify and local-ELF differential evidence separately. Do not weaken that field to make a native batch look green.

This finite pilot uses the supported original ELF, fresh unmodified resource/save inputs and no mods. Current adapters fingerprint at installation, while per-entry probes certify evidence but do not prevent native execution after a later code mutation. Runtime patching is outside this experiment, as in NATIVE_EXPERIMENT.md. A per-call execution guard or coherent invalidation contract is required before claiming modified-code compatibility or broader/default activation. An observed uncertified call cannot pass this batch.

## Batch B: a portable vector-metric module

This family implements length, squared length, distance and squared distance for three-component vectors, subject to the exact observed original semantics. It is a coherent math boundary, not a claim that player motion, physics or AI has migrated.

- **VEC-001 — Certify the four contracts offline.** Recheck the full spans at `0x08877244` (32 bytes), `0x08877264` (28), `0x08877280` (40), and `0x088772A8` (36), including return delay slots. Identify each input pointer/word, stack scratch byte, result and changed GPR/FPR/VFPU/control field. Establish prefix and rounding behavior with bounded local-original-code execution. Record supported cases, rejects/fallbacks and an independent oracle limitation statement before implementing.
- **VEC-002 — Implement the portable core and adapters.** Core APIs exchange vector values/raw bits and own no Runtime, GuestMemory or CPU context. Adapters handle the certified guest layout and state effects. Test zero/signed zero, extrema, subnormals, infinities/NaNs, rounding/prefix behavior, aliases, stack/source overlap, canaries, return behavior and deterministic randomized inputs against the original spans. Unsupported conditions must be explicit; changed fingerprints cannot silently install. Default remains off. A green suite based only on implementation-shaped examples is insufficient.
- **VEC-003 — Observe and prepare its related acceptance batch.** After the offline module gate, extend certified probe identities and mode metadata deliberately. Static caller evidence is not enough to invent a user route. First discover real calls through bounded related observations, then require only supported demonstrated triggers in a finite case. Retain all existing observation bounds and guard behavior. New user testing follows the same paired workflow and does not silently broaden the earlier acceptance claim.

VEC-001 can proceed independently of the user's Batch A execution once the initial inventory is accepted. VEC-002 depends on its contract audit; VEC-003 depends on that implementation and the mode-aware delivery/report policy. The exact new switch names and sample counts are recorded when the contract audit resolves the interfaces; this planning document does not fabricate them.
